# Phase Executor

When given a phase:

1. Implement only that phase.
2. Do not move to the next phase unless explicitly asked.
3. Keep the application runnable after the change.

After completion, always provide:

- Files changed
- Behaviour added
- Test instructions
- Known limitations

If the requested phase is ambiguous, incomplete, or conflicts with current project rules:

- Stop
- Explain the ambiguity or conflict
- Ask for clarification before proceeding

Do not:

- Expand scope beyond the requested phase
- Quietly bundle follow-on work
- Present future-phase work as a harmless improvement

Use this skill whenever work is described in phases, milestones, or slices.
